## 已确认的选择

### Q1 A：计数并入刷新信息行

- 取消“目前已加载 N 个新版本”的独立一行。
- 在现有上次刷新信息旁显示简短计数，例如：`上次刷新 今天 10:30 · 新版本 1`。
- 使用现有次要文字样式；完整含义由无障碍描述提供（可见文案是简短形式，
  `timelineLoadedNew` 保留为完整的计数描述并带 live region）。
- 计数含义沿用当前逻辑：当前已加载窗口内，符合当前搜索和筛选条件，且发布时间晚于
  Timeline Refresh Baseline 的去重新版本数。

### Q2 A：仅时间线

- 为时间线增加顶部下拉刷新。
- 保留工具栏刷新按钮作为桌面与无障碍操作入口。
- 仅在列表实际顶部继续下拉时触发；少量内容和可刷新的空结果也应能触发。

### Q3 A：右下角浮动回顶部按钮

- 离开顶部一定距离后显示图标按钮，无常驻文字标签。
- 返回当前搜索和筛选结果的真正顶部，不触发刷新。
- 使用现有 Material 图标、主题颜色和标准点击区域，提供“回到顶部”的提示与无障碍名称。
- 避开底部导航、安全区和“加载更早”操作；最后一项及其操作应可完整滚入可见区域。

### Q4：计数边界与窄屏排版

- 用户明确要求窄屏也显示完整时间文案，不采用简写或省略。
- 在刷新信息旁显示计数，正常手机宽度不新增独立信息行。
- 沿用现有零计数隐藏行为；没有刷新基准时不显示新版本数。
- 大字号下优先完整呈现文字，必要时让同一信息段自然换行，不把计数重新做成固定独立一行。
- 保留既有筛选入口，计数变化以完整语句提供无障碍状态播报。

### Q5：回顶部按钮的出现与移动

- 以列表可视区域高度为一屏；距离真正顶部超过一屏时显示，回到一屏以内时隐藏。
- 达到显示条件后持续显示，不随滚动方向或停顿隐藏。
- 点击以 240ms 返回真正顶部；系统要求减少动画时直接定位。

### Q6：刷新过程与结果反馈

- 下拉和工具栏按钮共用刷新行为，保留当前搜索及筛选。
- 刷新期间保留旧内容，用进度指示反馈，并阻止重复刷新。
- 刷新获得可用结果后回到顶部；完全失败时保留旧内容及阅读位置，提供错误与重试入口。
- 部分仓库失败继续使用既有失败提示；加载更早和重试不改变刷新基准。
- 成功时通过内容和计数更新反馈，不额外弹出成功提示。

## 已确认的视觉细节（Q7）

### 顶部信息

- 保留现有两排布局：第一排搜索、正文搜索切换和刷新；第二排完整刷新时间、分隔点、新版本数和筛选入口。
- 示例：`上次刷新 今天 10:30 · 新版本 1`，不改写时间的现有本地化语义。
- 时间与计数均完整使用 Dense Chrome 的 `meta` 字体角色：12 / 1.33、w400、`onSurfaceVariant`。
  用户要求遵守设计规范后，取消上一轮提案中的计数数字 w600，以符合 `meta` 角色的定义。
- 不使用徽标底色或未读红点，信息行高度由既有筛选按钮决定。

### 下拉与刷新中

- 搜索和信息行固定，仅列表区域响应下拉。采用标准下拉阈值和释放手感，不加入自定义拉伸或回弹。
- 下拉过程中在列表上沿浮现圆形进度指示，随着手势显露；未达到触发阈值就松手时收回，不发请求。
- 达到阈值松手后进度指示继续旋转；使用主题 `primary` 和现有容器底色，不加阴影。
- 下拉触发时只在列表顶部显示进度，工具栏刷新按钮禁用且不重复转圈。
- 工具栏按钮触发时只在按钮原位显示进度，按钮点击区域及工具栏尺寸保持稳定。
- 有旧内容时保持卡片原有亮度、可滚动和可阅读，不盖遮罩或替换成整页加载界面。
- 首次没有任何内容时沿用已有页面级加载组件。

### 完成与失败

- 获得可用结果后更新列表和计数，收起进度；用户已在顶部时直接呈现结果，避免白屏或卡片逐个入场。
- 工具栏刷新从深处发起时，成功后用与回顶部按钮相同的 240ms 移动返回顶部。
- 计数更新不跳动、不闪烁，保留原有上次刷新分界标记及新版本计数的领域含义。
- 完全失败时让进度恢复为刷新按钮，保留卡片和阅读位置，用现有紧凑错误样式提供重试。
- 错误提示不得抢走焦点；提示区域出现也应维持用户正在阅读的卡片位置。
- 部分成功显示已取得的结果，并继续显示既有仓库失败提示。

### 回顶部按钮

- 48dp 圆形点击区域，20dp Material `arrow_upward` 图标。原方案的 `vertical_align_top` 是文本对齐字样，
  实现后按用户反馈修订：字形仍属 Material Icons 同一家族、同一 20dp `iconAction` 尺寸，不是规范扩展。
- 底色为 `surfaceContainerHigh`，图标为 `onSurface`，外圈使用 `outline` 的 1dp 边框；不加阴影。
- 右侧与底部使用 `bandGap`（24），而不是卡片的 `gutter`（16）；底部距离从导航栏和系统安全区上方计算。
  实现后按用户反馈修订：按 gutter 对齐时圆形轮廓正好压在卡片右边界、图标又正好压在卡片正文右边界，
  控件看起来像卡片列的一部分而不是浮在上面的操作。
- 超过一屏时以 120ms 淡入，回到一屏以内以 120ms 淡出，不缩放或弹跳。
- 点击采用 240ms 减速滚动，停在最新日期分组和第一条可见结果处。
- 手动滚动可以中断回顶部动画；减少动画模式直接定位并即时切换显隐。
- 列表末尾预留按钮所需空间，确保“加载更早”及最后一张卡片可完整滚到按钮上方。
- 悬停、键盘焦点、点击和禁用态沿用现有主题；亮暗模式均使用同一套语义色角色。

## 规范符合性与扩展审核

| 方案项                   | 既有令牌依据                                           |
| ------------------------ | ------------------------------------------------------ |
| 时间和计数的文字样式     | `meta`，w400，`onSurfaceVariant`                       |
| 按钮 48dp 点击区域       | `heightStandard`                                       |
| 按钮图标 20dp            | `iconAction`，单一 Material 图标家族                   |
| 按钮右侧、底部间距 24dp  | `bandGap`（浮动控件不压在卡片列的对齐线上，理由见上）  |
| 圆形轮廓                 | 使用 `CircleBorder` 的控件不另设圆角数值               |
| 主题底色、图标色和外边框 | 语义色、`outline`、唯一 1dp 线宽                       |
| 无阴影、按主题分层       | 使用 surface 台阶和规则线表达层级                      |
| 显隐 120ms、回顶 240ms   | 复用允许的动效时长，遵循减少动画设置                   |
| 刷新进度与错误呈现       | Flutter AGENTS：控件级进度，复用现有页面状态与错误样式 |

当前方案无需新增字号、颜色、间距、线宽或动效时长，也无需新增规范例外。
计数同排、下拉刷新与回顶部是现有规则的组合使用。

如实现中出现确有必要的规范扩展，先说明新增角色或例外、具体用途、现有规则无法覆盖的原因及
替代方案，提交用户审核；收到明确批准后才更新规范和实现。不将“已确认本设计”视为对后续
规范扩展的概括授权。

## 实现时必须核对的现状（实现后已处理）

- `lib/timeline/timeline_toolbar.dart`：计数原先独占第三行；现在并入刷新信息行，简短计数为可见文案，
  `timelineLoadedNew` 保留为完整无障碍描述（live region）。
- `lib/timeline/timeline_screen.dart` 使用版本身份和卡片内偏移保存 Timeline Reading Position；
  刷新入口原先在发起时就清除锚点并重建列表，现在改为结果落地后判定：可用结果回到结果顶部，
  完全失败保留卡片与位置。
- 时间线采用带 `center` 的 `CustomScrollView`，锚点之前的内容可能位于负滚动范围。
  按钮显隐与下拉边界都以 `minScrollExtent`（真正内容顶部）计算，而不是滚动偏移零。
- 已有时间线分页通过“加载更早”按钮触发；列表末尾现在预留按钮所需空间（24 + 48 + 24），
  最后卡片与“加载更早”可以完整滚到按钮上方。
- 完全失败时不再叠加上方的仓库失败横幅：整轮失败由列表末尾的紧凑错误与重试表达，
  上方横幅只在部分成功时出现，避免错误区域把正在阅读的卡片推下去。
