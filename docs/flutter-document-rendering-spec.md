# Flutter：修复原生文档布局、接入 Rust SVG 并统一阅读样式

## Parent

https://github.com/pynickle/gitpulse/issues/132

## Problem Statement

Flutter 的 README 与发布说明共用原生文档组件，但真实 README 会丢失作者的居中布局，部分 SVG 徽章出现巨大字形与裁切，已经影响内容可读性。原 #136 只覆盖字重、行内代码和代码卡片，并将 SVG 可用视为既有前提；实际调查证明该前提不成立。

已确认两处独立问题：文档清洗删除了现有 HTML renderer 已支持的 align；SVG 后端会错误处理文字缩放，且内嵌 SVG 图标存在兼容缺口。只调整样式或更换 Markdown parser 无法同时解决这些问题。

## Solution

保留 Markdown→净化 HTML→Flutter 原生排版和现有代码组件，恢复受支持的作者布局语义；仅在文档 SVG 图片边界引入 Rust resvg，将完整 SVG 渲染为按显示尺寸生成的图片，再由 Flutter 显示。README 与发布说明使用同一实现，并继续完成 #136 原有的阅读字重、行内代码和代码卡片改进。

目标是作者布局与内容正确、交互仍为原生、视觉遵循 GitPulse Reading Surface，而非逐像素复制 GitHub 网页。此规格替代 #136 原有“完全不换依赖”的限制，但不更换 Markdown parser 或整页 HTML 布局引擎。

## User Stories

1. 作为 README 读者，我希望作者设置的居中标题与段落保持居中，以便页面结构不被改写。
2. 作为发布说明读者，我希望同样的文档内容获得与 README 一致的排版，以便不用适应两套规则。
3. 作为徽章读者，我希望版本号、Star 数和说明文字清晰完整，以便读到真实信息。
4. 作为徽章读者，我希望内嵌 GitHub 图标仍显示，以便识别徽章的含义。
5. 作为图片读者，我希望显式尺寸、原始比例和容器宽度限制得到正确处理，以便图片不被无故撑满或裁切。
6. 作为手机用户，我希望多个行内徽章在窄窗口自然换行，以便每个徽章仍可阅读和点击。
7. 作为高像素密度设备用户，我希望徽章按实际显示密度绘制，以便正常阅读尺寸下保持清晰。
8. 作为 Windows 用户，我希望与 Android 使用相同的文档能力，以便不会因平台不同丢失徽章。
9. 作为主题用户，我希望随主题变化的 SVG currentColor 正确更新，显式颜色保持原样，以便图形不会染错颜色。
10. 作为文档读者，我希望图片加载失败时有局部可读回退，以便其余正文仍能阅读。
11. 作为阅读者，我希望滚动和页面操作不被原生 SVG 解析阻塞，以便长文档仍可顺畅使用。
12. 作为选择文字的用户，我希望正文仍可选择和复制，以便引入 Rust 不会把整篇文档变成图片。
13. 作为代码读者，我希望正常正文、标题与强调文字具有清晰的字重层级，以便快速扫描内容。
14. 作为代码读者，我希望行内代码有主题底色、圆角和留白，以便与普通文字区分。
15. 作为代码读者，我希望代码块具有统一边框、圆角、间距和语言／复制操作区，以便直接操作。
16. 作为代码复制用户，我希望完整保留原始空白、换行和内容，以便复制结果可以直接使用。
17. 作为长代码读者，我希望代码保持原始换行并可横向滚动，以便代码结构不被自动折行改变。
18. 作为仓库文档读者，我希望相对图片、相对链接和锚点继续按仓库 revision 与文档目录解释，以便导航目标正确。
19. 作为表格和折叠内容的读者，我希望表格、对齐和 details/summary 仍可使用，以便已有文档能力不退化。
20. 作为大字号及辅助功能用户，我希望文字、链接和图片替代文本仍可访问，以便原生阅读能力保留。
21. 作为维护者，我希望从干净检出就能构建 Android 和 Windows 的原生依赖，以便发行不依赖开发机手工复制的二进制。
22. 作为已有离线发布说明的读者，我希望仍能阅读保留的正文，以便图片渲染变更不改变已有离线正文承诺。

## Implementation Decisions

1. **共用所有者**：继续由 ReleaseDocument 及既有文档准备逻辑服务 README 与发布说明；NativeCodeBlock 继续拥有高亮、原文、复制和横向滚动。保持既有 Reading Measure、15sp／24sp 正文与阅读字阶；原仓库页重构不是前置条件。
2. **作者布局**：按标签与枚举值保留受支持的 align，覆盖标题、段落、容器及表格对齐；保留图片 width/height，按容器限制等比显示。只恢复有明确用途的文档属性，继续执行既有净化与 URL 规则，不直接放行任意 style、脚本或网页 CSS。
3. **SVG 后端决策**：文档 SVG 采用上游 resvg 直接渲染为像素，不将本轮目标改成 jovial_svg、文字转路径补丁或浏览器引擎。其他应用图标无需一并迁移。该替换不扩展成通用跨语言框架。
4. **窄接口**：以 SVG 字节、目标像素尺寸、主题 currentColor 与字体配置为输入，输出图片数据／尺寸或可局部处理的错误。优先使用 resvg 官方 C API 经 Dart FFI，或必要的薄 Rust 导出层；桥接选择属于实现细节。单纯为此功能不引入 Node 运行时或必须部署的服务端转换服务。
5. **实际兼容要求**：完整处理固定徽章中的文字变换、textLength 与内嵌 data SVG 图标；同时保留已支持的普通位图、SVG intrinsic size、显式尺寸、带链接图片、无 .svg 后缀的动态 SVG URL，以及失败 alt 回退。不得以不抛异常或显示一个有色矩形代替这些验收。
6. **主题与资源**：沿用现有匿名资源获取和仓库资源解析。Rust 只处理传入字节和明确提供的字体，不自行获取网络／本地文件资源；SVG 内嵌图形可以解析。GitPulse 认证 cookie、CSRF 及会话头不进入文档图片请求。
7. **字体与发行**：明确并记录可分发字体或平台字体的加载与回退策略，Android 不得依赖开发机 Windows 字体路径。选择并固定兼容的上游 resvg 版本与原生依赖；Windows Node 绑定实验的旧 fork 不是生产依赖依据。原生库随各自 Android ABI 与 Windows 发行包交付，复用现有发布平台与构建方式。
8. **绘制生命周期**：原生解析／栅格化在不阻塞 UI 的执行路径完成；按实际显示尺寸和 device pixel ratio 生成图片，主题或尺寸改变后得到匹配结果。复用或局部缓存已完成的同输入结果，避免普通 rebuild 重复下载、解析和绘制；不新增完整离线图片缓存系统。
9. **既有交互**：文字选择、链接导航、表格、折叠内容、图片语义、代码原文复制和横向滚动保持。仅 SVG 变成图片，整篇文档仍由 Flutter 排版；Release Drawer 高度、顶栏和手势不变。
10. **原样式要求**：正文保持正常字重，加强标题与强调；行内代码使用主题底色／圆角／留白，代码块使用共享圆角、细边框、内边距和语言／复制区，沿用高亮失败与未知语言的可读回退。通过共享语义主题和令牌实现，不建立页面私有样式副本。
11. **平台与性能证据**：功能交付目标是现有发行平台 Android 与 Windows。记录同一固定文档的冷／热 SVG 加载、重复构建和滚动表现；不预设 Rust 必然更快，不把 Node 宿主结果或平台标签当作移动端集成结果。原生依赖可构建和包内可加载必须有自动化证据；真机未测部分单列。
12. **范围与工作方式**：本次使用一个自包含 #136 规格，不再拆子票。布局、Rust 图片和样式在同一共用阅读表面逐个行为切片实现；已由用户取消的 #137 时间线纵轴不再属于 #132 的交付目标。

## Testing Decisions

主要验证入口沿用现有 ReleaseDocument Widget 挂载：输入真实 Markdown、仓库文档上下文和可控图片服务，断言用户实际看到的对齐、尺寸、图片像素与交互。低层测试仅补充该入口不易区分的 Rust 核心／FFI 契约；不建立平行文档测试框架，也不读取生产源码字符来断言实现。

1. **布局回归**：先证明作者居中被删除的失败行为，再验证准备后的文档实际渲染为居中；覆盖标题、段落、表格对齐、64×64 显式图片与行内徽章换行。文档转换测试断言函数输出的语义，Widget 测试测量真实渲染结果。
2. **真实 SVG 像素**：将研究中的完整固定 Shields 字节及最小文字缩放样例纳入持久化 fixture，测试无需访问实时 Shields。使用确定的字体与可检查的图像区域／等价变换断言，证明文字没有撑满裁切、嵌套 logo 实际绘制，textLength 生效。PNG 存在、不抛异常、源码包含 resvg 都不算通过。
3. **真实原生调用**：至少一个宿主测试经过实际编译的 Rust／C 动态库，而非只替换 renderer 服务。验证图片尺寸、字节格式／通道、错误回退以及重复调用的结果；原生核心与挂载文档两端均有覆盖。
4. **既有文档契约**：沿用文档准备、release document、字阶、代码内容／复制、仓库屏幕和发布说明测试。覆盖位图、无扩展名 SVG、相对资源、currentColor 与显式色、失败 alt、浅／深主题切换、代码横滚／精确复制、链接和正常正文选择。
5. **平台交付**：从干净检出验证现有 Android／Windows 构建链可编译并打包 native 库；CI 检查对应架构的库加载／调用，而不只检测文件存在。本地宿主不能代替 Android 证据；可编译／可加载也不等于真机阅读已测。保留有用的失败日志，明确尚未运行的设备检查。
6. **检查方式**：执行适用的 Flutter 分析、Dart 格式检查和 Flutter 测试，测试进程串行；Rust 改动执行对应格式、静态检查与实际行为测试。原生构建／打包验证限定本功能与既有 CI，不主动启动浏览器、Marionette 或发行部署。
7. **性能边界**：以同一固定输入区分下载、原生渲染和 Flutter 布局时间，记录首次与缓存后表现以及主题／DPR 变化。用行为测试确认普通 rebuild 不重复工作；不以跨设备绝对毫秒阈值或未经本项目验证的库宣传数字作为通过条件。

## Acceptance Criteria

- [ ] README 和发布说明均保留支持的作者居中、表格对齐、图片比例／尺寸和行内徽章布局。
- [ ] 真实完整 SVG 徽章通过实际 resvg 后端渲染；文字缩放、textLength 和嵌套图标均有行为断言。
- [ ] Android 与 Windows 的 native 依赖可从干净检出构建、随包交付并有实际调用证据；字体配置不依赖开发机专有路径。
- [ ] SVG 按显示密度保持清晰，主题更新 currentColor 且不改显式色；普通 rebuild 不重复完整工作。
- [ ] 原有匿名资源、相对链接／图片、失败 alt、文字选择、表格和折叠内容契约保留。
- [ ] 原 #136 的字重、行内代码、代码卡片、高亮回退、横向滚动和精确复制要求完成。
- [ ] 共享主题、阅读字阶、手机／宽窗口和中英文表现得到验证。
- [ ] 已有静态检查、格式与适用测试通过，平台／真机／性能未验证部分如实列出。

## Out of Scope

- 更换 Markdown parser、整页 HTML renderer，或接入 WebView、Blitz、Servo、WebF。
- 将整篇文档绘成位图，或移除原生文字选择、链接与代码组件。
- 逐像素复制 GitHub 的全站 CSS；支持任意 HTML/CSS／动态 SVG／脚本。
- 服务端图片代理、Node 转换服务、全量离线图片缓存或新的用户设置。
- 重写认证、API、数据库、缓存成员、导航、Release Drawer 顶栏／高度／手势。
- #137 的日期节点／连续纵轴，以及其他已完成的 #132 子任务重做。
- 浏览器／Marionette、设备安装、签名发行、发布分发，以及未运行的真机验证声明。
