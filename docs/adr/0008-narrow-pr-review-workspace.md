# Narrow PR Review Workspace keeps one scrolling diff and two sheets

On a wide viewport the PR Review Workspace is three panes: changed files, a Split Diff, and the review submission. Those panes do not fit a phone, including a landscape phone around 930px wide. At and below 1024px the Diff Viewer stays on screen as a Unified Diff, and a Review Bottom Bar opens the changed files and the review submission in separate sheets.

A file-list master screen was rejected because it replaces the continuous diff with one file at a time. A header file switcher plus a persistent submit footer was rejected because the footer spends height on every line and a compact switcher is a poor tree. Keeping Split Diff and scrolling both sides was rejected because comments attach to the new side, which would start off screen. Wrapping narrow lines was rejected because it breaks indentation. Hiding the bar while the diff scrolls, edge-swipe, and a persistent "+" were rejected. The Review Inline Composer stays under its Diff Row; it does not dock as a second bar above the keyboard.

**Consequences**: 1024px matches the Detail Sidebar sheet. It does not change Dashboard Home's 860px cutoff (ADR 0004), and the Release Drawer stays at 860px. The Review Bottom Bar is not the Dashboard Home bottom bar rejected in ADR 0005: that bar was for six tabs. ADR 0001 still seeds a wide Review Inline Composer from its setting. A narrow one is always Tabbed Layout and does not write the setting back. The Review Submit Composer stays always Tabbed Layout. Timeline review diffs are unchanged. A tap on commentable code opens the inline composer, a horizontal pan only scrolls, and a long-press then drag selects text.
