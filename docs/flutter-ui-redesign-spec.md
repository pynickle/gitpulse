## 2026-10-27 范围修订

剩余 [#136](https://github.com/pynickle/gitpulse/issues/136) 已扩展为 [原生文档渲染规格](flutter-document-rendering-spec.md)：保留现有 Markdown parser、净化 HTML、Flutter 排版与代码组件，修复作者布局属性丢失，仅在 SVG 图片边界引入 Rust resvg，并完成原字重、行内代码和代码卡片要求。这修订实现决定 16 及原 Out of Scope 的依赖限制；不允许由此更换整页布局引擎或引入 WebView。架构边界见 [ADR 0027](adr/0027-flutter-native-document-svg-boundary.md)。其余已完成子任务和既有产品语义不受本修订影响。

## Problem Statement

Flutter App 当前的设置表格、关注页菜单和追加加载、仓库详情层级、Markdown 代码容器，以及时间线和筛选的呈现缺少一致的视觉组织。用户希望设置更易扫描、关注页可以直接切换来源和排序并按页浏览、仓库身份和动作更清晰、README 与发布说明更精致，以及按日期组织的时间线更容易追踪。

本次还需要为未来主题系统留好扩展位置，避免每个页面复制颜色和样式；同时保持现有原生组件、深色模式、账号与设备偏好、离线缓存和导航行为。

## Solution

在现有绿色 Material 主题与共享视觉令牌上完成 Flutter UI 重构：设置使用无重复副标题的独立圆角卡片；关注页采用网页的固定来源／排序栏、独立滚动结果区和固定页码栏；仓库详情显示 owner 头像与分行身份，保留 Home，并将发布列表、发布关注、分享固定在同一操作行；统一改进 README 与发布说明的 Markdown 样式；时间线加入日期节点与左侧连续纵线；筛选改用方框复选框并移除顶部已选仓库标签行。

参考图用于传达层级和布局，不要求逐像素复刻。已有原生组件与目标大体一致时直接复用，忽略生成图和网页截图中的偶然内容差异。

## User Stories

1. 作为 Flutter 用户，我希望 Android 与 Windows 使用一致的视觉层级，以便在设备间切换时快速找到操作。
2. 作为深色模式用户，我希望新界面随浅色／深色主题适配，以便表面、文字和代码保持可读。
3. 作为设置页用户，我希望每项设置位于清楚分组的圆角卡片中，以便快速扫描需要的选项。
4. 作为设置页用户，我希望只看到标题与控件，以便不必阅读重复解释用途的副标题。
5. 作为设置页用户，我希望看到当前后端状态、地址和复制入口，以便确认并复用连接目标。
6. 作为设置页用户，我希望仍能更换后端并执行账号操作，以便连接管理能力完整保留。
7. 作为未登录用户，我希望仍能使用连接和设备设置，以便无需登录即可配置本机。
8. 作为多语言用户，我希望清晰选择跟随系统、English 和简体中文，以便快速选择界面语言。
9. 作为外观设置用户，我希望清晰选择跟随系统、浅色和深色，以便立即应用需要的外观。
10. 作为缓存用户，我希望用加减按钮每次调整一天并立即应用，以便快速微调保留期。
11. 作为缓存用户，我希望点击天数直接输入并确认，以便无需连续点击几十次来大幅调整保留期。
12. 作为缓存用户，我希望输入受 1–90 整数范围约束，以便不会应用无效的保留策略。
13. 作为离线用户，我希望保留天数仍是本机选择并可离线修改，以便后端不可达时也能管理历史。
14. 作为设备用户，我希望语言、外观、关注视图和保留期在清缓存、退出和切换后端后保留，以便不用反复设置。
15. 作为缓存用户，我希望仍可清除当前账号的本机时间线缓存并获知实际失败，以便管理本机数据。
16. 作为关注页用户，我希望通过顶部两段式控件切换 Starred 与 GitHub 仓库搜索，以便直接选择发现仓库的来源。
17. 作为 Starred 浏览用户，我希望直接切换收藏时间与更新时间排序，以便无需打开菜单即可改变顺序。
18. 作为 Starred 浏览用户，我希望直接选择升序或降序，以便快速翻转浏览顺序。
19. 作为搜索用户，我希望保留现有仓库搜索与仓库 URL 查找，以便继续使用熟悉的查找方式。
20. 作为仓库浏览用户，我希望以页码替代加载更多，以便直接访问不同页且不会不断累加列表。
21. 作为长列表用户，我希望顶部控件与底部页码在结果滚动时仍可操作，以便无需滚到列表两端。
22. 作为分页用户，我希望上一页、当前页数字段与下一页同处一枚扁平页码胶囊，总页数在旁边以文字说明，以便在同一处翻页或直接输入页码。
23. 作为分页用户，我希望总页数未知时只看到可确认的页面与导航，以便界面不会编造末页。
24. 作为分页用户，我希望成功翻页后从新页顶部开始阅读，以便不会停留在上一页的滚动深处。

## Implementation Decisions

1. **视觉基础**：继续使用现有绿色 Material 主题和浅／深色适配，统一共享语义颜色、文字角色、形状、间距与交互状态。重点验证 Android 手机与 Windows 宽窗口；复用等价原生组件，不为截图微小差异另造组件。
2. **未来主题**：通过既有主题和令牌所有者集中新增视觉角色，仅补充已确认设计所需角色。代码高亮主题选择由共享呈现层控制；不散落品牌色常量或各页面样式副本。主题选择器、预设、自定义配置与插件框架留待以后。
3. **设置卡片**：用后端、语言、外观、保留天数、时间线缓存等独立圆角卡片替换表格。使用领先图标、标题和直接控件。保留后端状态、URL／复制、更换后端与账号操作；删除重复用途说明。实际失败和阻塞仍保留必要反馈。
4. **设置可用性**：共享账号能力继续支持未登录连接／凭据流程；设备偏好在后端不可达时仍可使用，语言与外观在连接之前生效。当前账号缓存清理继续遵守原登录和账号边界。
5. **保留期输入**：减／加每次一整天并立即应用；点击数值允许直接输入并确认后应用。默认 30，范围 1–90；边界禁用相应调整，拒绝非法值。复用设备偏好控制器、串行保存、失败反馈与缓存初始化／裁剪规则。此项明确替换旧规格中“所有修改都通过输入框确认”的交互要求。
6. **关注页布局**：顶部固定来源与排序，中间拥有唯一结果滚动区域，底部固定页码。手机页脚关注数量入口打开既有 Followed Repositories 面板；宽窗口保留既有并列管理面板。保留发现卡片、关注管理与 Compact／Detailed 视图。
7. **关注页控件**：来源使用 Starred／GitHub 仓库搜索分段选择；仅 Starred 显示收藏时间／更新时间分段排序和升／降序按钮。手机来源独占第一排，排序和方向共享下一排。搜索保留输入、提交／清除与仓库 URL 查找。
8. **分页契约**：复用现有仓库 API 的 page、perPage、hasPrev、hasNext、totalCount、totalPages，补齐 Flutter DTO 映射。每页仍为 30 条，翻页替换结果，不追加。总数可为空，URL 单项查找可无分页；无需新服务端分页协议或数据库结构。
9. **页码呈现**：上一页、当前页数字段与下一页同处一枚扁平细线页码胶囊（比工具栏控件更扁，格宽大于格高，ADR 0026），总页数以「共 N 页」文字写在胶囊之外；数字始终是字段且即刻显示正在请求的页码，聚焦只改胶囊描边色；总页数未知时不画出总页数，无分页单项结果不显示虚构页码，仅有一页时整枚胶囊不显示。
10. **分页状态**：来源各自保留结果和页码；改变排序、方向或搜索词回到第一页。成功翻页返回结果顶部；进入新页码时整页显示加载，本页刷新沿用下拉刷新动画而非进度条；失败时以整页错误页和唯一重试取代列表，失败目标页不能成为当前页，胶囊在错误页上不显示。复用既有请求生命周期和会话边界。
11. **仓库数据映射**：在现有仓库数据来源上补齐稳定仓库身份、owner 头像以及规范 GitHub URL 所需映射，不建立平行仓库服务。展示真实 owner 头像，不把生成图装饰图当作必需项目图标。
12. **仓库字阶与内容**：owner 14sp、仓库名 22sp 半粗体、描述 14sp；owner 与仓库名分两个逻辑行，长名称可再换行，不截断或自动缩小。README 正文保留 15sp／24sp。保留语言、Star、Fork、可用 Watcher 数据和实际 revision／路径；README 失败继续局部呈现。
13. **单行仓库操作**：Repository Release List、Release Follow 和 Share 在窄屏与宽屏都保持同一行。发布列表是主要操作并占主要宽度，关注与分享用紧凑内边距、间距和简洁本地化文字适配，保留有意义的点击区域与名称。用户明确拒绝发布列表独占一行、另外两项下一行的回退。
14. **关注与分享**：复用共享 Release Follows 确认模块与稳定仓库身份，保持现有限制、服务端成功后确认及失败保留集合的规则。Release Follow 独立于 GitHub Star／Watch，采用书签类状态表达。分享规范 GitHub 仓库 URL，可用时调用系统分享，否则提供复制链接。
15. **仓库导航**：保留 Back 和右上角 Home。Home 回 Release Timeline；Back 恢复进入仓库时的上下文，包括原 Release Drawer，不引入固定返回目标。
16. **Markdown 所有权与依赖**：README 与发布说明继续共用 ReleaseDocument 及现有 Markdown→净化 HTML→原生渲染链，代码由 NativeCodeBlock 处理。现有依赖已有高亮、复制、横向滚动和 SVG 能力，先改样式；仅在出现具体无法实现的要求时另行评估替换。
17. **Markdown 阅读样式**：正文保持正常字重，明确更强的标题与强调字重，保留既有阅读字阶和紧凑标题节奏。行内代码增加主题底色、圆角和适当留白；代码块增加共享圆角、细边框、内边距及清楚的语言／复制区。保持高亮、普通文本回退、原始换行、横向滚动和精确复制；装饰不得改变复制源文。
18. **时间线结构**：日期组左侧连续纵线和日期节点贯穿记录。手机单列，宽窗口按原断点保持同日期组内的两／三列卡片。保留时间顺序、卡片信息、刷新分界和阅读位置；各列不成为独立时间流。
19. **时间线筛选**：仓库行末从选中时出现的圆形勾改为常驻方框 Checkbox，选中态使用主题色；删除列表上方全部已选仓库 chips。保留顺序、搜索、行选择、日期范围、隐藏预发布、全部清除及原有应用时机；筛选仍为本机显示操作，不触发数据请求。
20. **既有语义边界**：Device Preferences 仍属于安装；Release Follow 与 Timeline Refresh Baseline 继续按账号共享。保留 Shared Timeline Window、缓存成员、离线启动、部分失败、清缓存、阅读恢复与按压反馈规则。页码替换只针对关注页，首页加载更早记录机制不变。
21. **本地化与文档**：中英文控件使用现有数字和时间格式，并提供语义名称。同步修正旧的设置表格规范。ADR 0025 记录本轮设置布局反转和共享主题边界；既有阅读表面、关注确认、设备偏好、保留期与按压反馈决定继续适用。

## Testing Decisions

好测试必须执行真实代码并断言外部行为：用户操作后的渲染内容、可点击位置、路由、请求参数／载荷、复制／分享内容或设备设置结果。不读取源码匹配字符串，不 mock 被修改模块本身来证明功能成立。

优先复用一个主要入口：现有整应用／页面 Widget 挂载设施，配合已有设备偏好覆盖、可控会话与 HTTP 测试服务。共享文档继续用已有 ReleaseDocument Widget 渲染测试。沿用此前确定的 Flutter 行为验证方式，不新建测试框架或生产层测试接口，不为简单可逆样式逐个创建机械测试。

1. **设置与设备行为**：沿用 settings layout、device settings、device preferences、timeline cache settings 测试。覆盖卡片操作、无重复说明、语言／外观即时应用、天数加减与直接输入、边界／非法值、离线修改、保存失败和缓存清理。保留跨退出／清理／后端变更的设备偏好与保留期初始化／裁剪保护测试。
2. **关注页与请求**：沿用 release follows screen、session、HTTP、confirmed-follow 测试。实际点击来源、排序、方向和页码，断言请求参数及结果替换。覆盖独立来源状态、成功回顶、翻页整页加载、本页下拉重读当前页、失败整页错误与唯一重试、已知／未知总页数、URL 单项查询。滚动时测量顶栏／页脚仍在视口中，关注入口可操作。
