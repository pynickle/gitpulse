# Release Follows keeps its filters and its pager on screen at any width

The Release Follows page, the followed-repository list behind the Release Timeline's manage action, stacked its three segmented controls into three rows below 860px, and neither those controls nor the pager could be reached without scrolling to an end of the list. The page now runs as three bands inside one full-height flex box: a filter band, the scrolling card grid, and a footer band.

Below 860px the repository-source control owns the whole first row so its two halves stay equal, and the sort and order controls share the second row. The order control keeps its labels only for assistive tech, which holds that pair on one row in any locale. The footer band carries the pager next to a compact followed-count trigger that opens the same sheet the wide layout shows as a side panel; at and above 861px the trigger is dropped and the footer collapses whenever no pager is on screen.

Making the bands flex siblings rather than sticky children is the point of the change. The frame's `ScrollArea` never gave the page a definite height: SimpleBar sets no height on `.simplebar-content`, so a `height: 100%` descendant resolves to content height, a nested `ScrollArea` never becomes a scrollport, and `position: sticky` inside it has nothing to stick against. That fails silently rather than erroring, and it applied to the wide layout as well, where the filter band also scrolled away. The page now disables the frame's scroll area with `is-flush` and owns the only scroll container, so the height chain is explicit and no band depends on sticky.

Rejected: one horizontally scrollable filter row, because the order control would sit off screen; a sort sheet behind a single trigger, because it costs a second tap on the most used control; and keeping the pager inside the scrolling band as a sticky footer, because it would have to clear the bottom bar and only one of the two could own the bottom edge.

**Consequences**: The overlay frame no longer scrolls or pads this page, so the narrow bands run edge to edge and the wide layout supplies its own 1.5rem gutter. `ReleaseFollowsRepoGrid` no longer renders pagination or accepts pager props; the page owns that. The order control's icon-only presentation is CSS-only, so its labels stay in the DOM for assistive tech. Any other framed overlay that wants fixed bands should disable the frame's `ScrollArea` through `is-flush` or `is-clipped` and own its scroll container, rather than nesting a second `ScrollArea` inside it.
