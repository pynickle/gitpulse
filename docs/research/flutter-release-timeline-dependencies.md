# Flutter Release Timeline dependency research

Investigated on 2026-10-17 using Context7, official project documentation, and pub.dev package metadata. The user selected Riverpod, Drift/SQLite, Dio, GoRouter, flutter_secure_storage, cookie_jar/dio_cookie_manager, Dart markdown, flutter_widget_from_html_core, shiki_flutter's default Dart engine, fwfh_svg, json_serializable/json_annotation, SDK localization/intl, and the customized Material 3 direction. Other packages below remain alternatives or proposed supporting dependencies. Re-resolve stable SDK/package versions and compatibility at implementation time; do not treat this snapshot as a lockfile.

The applicability judgments above are engineering assessments, not benchmark results. See [Flutter's state-management overview](https://docs.flutter.dev/data-and-backend/state-mgmt/options).

Riverpod's [offline persistence](https://riverpod.dev/docs/concepts2/offline) remains experimental and does not replace an application's database schema, migrations, or connection rules. Selecting Riverpod must not silently select that experimental facility for this cache.

[Drift platform guidance](https://drift.simonbinder.eu/platforms/) states that recent Drift/sqlite3 versions bundle SQLite for the native platforms using native assets; older recipes adding `sqlite3_flutter_libs` should not be copied into this project without rechecking necessity.

No database proves timeline continuity. That is a domain rule over request provenance, repository identity, pagination, and retained history.

## Release-note and README rendering

The user requires common embedded HTML, including details/summary, images, and HTML tables. The following checks include inspection of published package archives, not only the current master branches. They have not been verified in a running Flutter UI.

| Candidate                                                                                                                    | Version observed | Verified capability                                                                                                                                   | Remaining work                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| [flutter_widget_from_html_core](https://pub.dev/packages/flutter_widget_from_html_core)                                      | 0.17.4           | Interactive details/summary including the open attribute; tables with colspan/rowspan and wide-table scrolling; images, pre/code, baseUrl and anchors | Theme, code highlighting/copy, localized missing-summary label, resource context, SVG integration                                                   |
| [flutter_html](https://pub.dev/packages/flutter_html) plus [flutter_html_table](https://pub.dev/packages/flutter_html_table) | 3.0.0 / 3.0.0    | Material ExpansionTile for details; table extension supports colspan/rowspan; images and basic code blocks                                            | Published details implementation does not honor open by default; relative resource URLs need explicit normalization; table is a separate dependency |
| [markdown_widget](https://pub.dev/packages/markdown_widget)                                                                  | 2.3.2+8          | Markdown widgets and an HTML-extension example                                                                                                        | HTML is not supported by default; the example does not establish a ready-made details/table contract                                                |
| [markdown](https://pub.dev/packages/markdown)                                                                                | 7.3.1            | Dart-side GFM/GitHubWeb Markdown-to-HTML conversion, including raw HTML                                                                               | Different parser from the web's Comark; application owns sanitization and content normalization                                                     |
| [@comark/html](https://comark.dev/rendering/html)                                                                            | 0.7.0            | Candidate server HTML output matching the existing Comark parser family                                                                               | Requires new Nitro rendering contract, security policy, versioned output, and resource-context processing                                           |

The core HTML package's details implementation was checked in its [0.17.4 release archive](https://pub.dev/api/archives/flutter_widget_from_html_core-0.17.4.tar.gz). See also [baseUrl API](https://pub.dev/documentation/flutter_widget_from_html_core/latest/flutter_widget_from_html_core/HtmlWidget/baseUrl.html) and the [flutter_html supported-elements reference](https://github.com/Sub6Resources/flutter_html/wiki/Supported-HTML-Elements).

The two useful parsing-location alternatives are:

- **Client parsing:** retain Markdown as the source, convert with Dart markdown, normalize resources, and render native HTML widgets. Offline re-rendering works without contacting Nitro, and backend changes are smaller. The app must maintain parser differences, GitHub-specific links, and safe content/protocol handling. The markdown package explicitly does not provide sanitization.
- **Backend parsing:** add Nitro Comark HTML output and retain Markdown plus versioned derived HTML. Parsing and resource semantics can be centralized, but there is new server work, CPU/transport cost, and an offline requirement to have fetched that HTML. Web Vue components, CSS, Shiki themes, and Mermaid behavior do not automatically transfer to native widgets. See [Comark HTML](https://comark.dev/rendering/html) and [its security plugin](https://comark.dev/plugins/built-in/security).

Repository investigation found no existing ready-to-call Nitro Markdown-to-HTML renderer. README and release APIs return raw Markdown; the existing full renderer is Vue-side Comark plus custom links/media and Shiki. `app/utils/sanitizeHtml.ts` has a narrow inline-element allowlist and strips details, images, tables, and pre; it is not a ready-made full-document sanitizer for either proposed route.

Common requirements for either route:

- Retain owner/repository/ref/path context. A single baseUrl does not fully express the difference between GitHub blob/tree links and raw image resources.
- Keep session credentials scoped to the selected backend; do not attach them to arbitrary external image URLs. Define permitted resource and navigation schemes explicitly.
- Navigate supported repository/release links in-app; send issues, pull requests, and other excluded subjects to the external browser.
- Include test cases for nested details, open, Markdown inside details, colspan/rowspan, relative links/images, code fences containing HTML, selection, anchors, and horizontal scrolling.
- Treat code highlighting/copy buttons and offline image availability as separate product requirements, not automatic consequences of basic pre/code or img support.

SVG badges can be added selectively with [fwfh_svg 0.16.1](https://pub.dev/packages/fwfh_svg) and [flutter_svg 2.3.0](https://pub.dev/packages/flutter_svg), without pulling in video/audio/iframe integrations. Current repository-master examples may use newer beta versions; implementation must resolve the selected stable release combination.

[flutter_widget_from_html](https://pub.dev/packages/flutter_widget_from_html) includes broader media integrations than the core package; they are not required merely to display details, tables, and ordinary images. [flutter_markdown_plus](https://pub.dev/packages/flutter_markdown_plus) alone cannot satisfy the accepted embedded-HTML requirement, and [flutter_markdown](https://pub.dev/packages/flutter_markdown) is discontinued. [gpt_markdown](https://pub.dev/packages/gpt_markdown) 1.3.4 is active but does not establish the required embedded-HTML/details contract, so it is not a primary candidate for this use case.

### Syntax highlighting alternatives

This initial shortlist was revisited after inspecting the user's flutter_highlight repository link. pd4d10/highlight.dart master has substantial 2026 changes and declares unpublished version 0.7.1, while pub.dev still offers 0.7.0. The old pub release, pinned new source, re_highlight, and new shiki_flutter 1.1.0 candidate passed small current-SDK headless probes, with different integration constraints. Do not infer current repository inactivity from the old published version. See [the expanded comparison and actual dependency-resolution results](flutter-syntax-highlighting.md). The user selected shiki_flutter's default pure-Dart engine; the table below is retained as alternative research.

| Candidate                                                     | Stable observed             | Benefit                                                                                                            | Cost                                                                                                           |
| ------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| [re_highlight](https://pub.dev/packages/re_highlight)         | 0.0.3, published 2024-02-05 | Dart implementation, broad language coverage including shell/PowerShell and C-family snippets, five native targets | Old stable release; documented highlight.js rules correspond to 11.9.0, not necessarily today's upstream       |
| [syntax_highlight](https://pub.dev/packages/syntax_highlight) | 0.5.0, published 2025-08-19 | TextMate grammar-based, five native targets                                                                        | Built-in set of 15 languages omits shell/PowerShell/C-family examples; super_clipboard adds native integration |
| No highlighting dependency                                    | SDK only                    | Select/copy/scroll can still work with plain code                                                                  | No syntax colors                                                                                               |

The clipboard dependency in syntax_highlight uses [super_clipboard](https://pub.dev/packages/super_clipboard), with a native Rust/binary pipeline and Android NDK requirements. This is not equivalent to a pure-Dart runtime dependency tree. Plain text copy can instead use SDK [Clipboard](https://api.flutter.dev/flutter/services/Clipboard-class.html). Highlighted spans, selection, language labels, copying, and overflow handling remain responsibilities of the app's code-block component.

### Latest compatible stable policy

Observed package constraints show a real incompatibility: build_runner 2.17.1 requires build >=5.0.0 <5.1.0, while current drift_dev 2.35.1 requires build <5 and json_serializable 6.14.1 requires build ^4.0.4. build_runner 2.17.0 is a newer-compatible candidate based on the inspected constraints; a complete project resolution has not been performed.

Use the newest jointly compatible stable versions, record any necessary older selection, and commit the application lockfile. Do not promise every independent latest version can coexist and do not use dependency_overrides merely to force that combination. Sources: [build_runner](https://pub.dev/packages/build_runner), [drift_dev](https://pub.dev/packages/drift_dev), [json_serializable](https://pub.dev/packages/json_serializable).

## Distribution candidates

For the first Windows release, a ZIP must contain the complete release directory, including executable, Flutter/plugin DLLs, and data; an executable alone is insufficient. It is easy to build and distribute but has manual installation/update behavior. Installer/MSIX/Store integration introduces a separate distribution lifecycle. See [Microsoft's Flutter packaging guidance](https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/guides/flutter).

An Android APK is appropriate for direct installation and user testing; an AAB is the Play Store route. Release signing identity must remain stable for future app updates. See [Flutter Android release guidance](https://docs.flutter.dev/deployment/android). No signing secrets or distribution accounts were inspected or created during this investigation.

## Platform verification boundary

Only Windows and Android are planned for hands-on debugging by the user. For Linux, macOS, and iOS, theoretical support means platform scaffolding, compatible dependencies, documented native prerequisites, and appropriate permissions/entitlements; it is not a claim that these builds have been run successfully. Consult [Flutter's supported-platform matrix](https://docs.flutter.dev/reference/supported-platforms) and each selected plugin's current setup instructions when creating the project.

SDK investigation found an official [Flutter 3.47.7 release record](https://github.com/flutter/flutter/issues/193851), but did not establish the absence of a newer stable patch from the SDK archive. Re-query the stable channel before choosing an SDK constraint.
