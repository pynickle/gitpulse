# Flutter 时间线远距离回顶

状态：已按用户确认的方案实现；Android 实际手感由用户验收，不进行设备调试。

## 已确认的行为

- 三屏以内连续减速上滑，沿用 240ms。
- 超过三屏省略中途内容：120ms 淡出，在不可见时定位真正顶部，再以 240ms 减速淡入，
  配合 12dp 的轻微位移。约 360ms，另需一次顶部布局。
- 仅列表过渡，顶部搜索、筛选、刷新信息及浮动按钮的位置保持稳定。
- 手动触碰或滚轮操作可打断；减少动画模式直接到顶。
- 回顶不刷新，不改变搜索、筛选、Timeline Refresh Baseline；落点是当前结果最新日期和第一行。

## 性能与正确性

原实现通过 `animateTo(minScrollExtent)` 在 240ms 内滚完整段距离，长距离会访问中途的
可变高度卡片。恢复 Timeline Reading Position 后，列表以阅读锚点为中心，顶部位于
负滚动范围，`minScrollExtent` 还可能是未构建行的估算。

远距离淡出后清除中心锚点，以新滚动控制器、新中心布局 Key 和偏移零重建惰性列表，
只布局顶部及缓存范围。保留原中心 GlobalKey 会把旧 SliverList 的深处布局原点带入新视口，
在一帧内回溯构建中途卡片，因此仅替换滚动控制器不够。
恢复过阅读锚点的列表保守采用同一过渡，以保证抵达真正顶部，不依赖估算距离。
这类列表的三屏阈值无法由当前 scroll metrics 精确判定。

淡入淡出和位移只更新绘制，不逐帧重建行模型、索引或卡片。重定位仍需一次 O(N) 行模型和
索引构造；不声称全部工作为 O(1)。旧控制器在帧末释放，旧滚动通知不能写回已离开的阅读位置。
取消过渡恢复完整可见性，并在下一帧保存用户实际位置。

## 视觉规范

120ms 和 240ms 复用现有动效档位。新增的内容位移角色
`GitPulseMotion.timelineReturnShift` 为 12dp，独立于布局间距，记录在
[ADR 0030](adr/0030-flutter-timeline-return-transition.md)。不增加弹跳、缩放或卡片逐个入场。

本设计更新 [原设计](timeline-refresh-navigation-design.md) 和
[原规格](timeline-refresh-navigation-spec.md) 中仅使用 240ms 连续回顶的约束。
其余刷新和阅读位置合同继续适用。术语沿用 [CONTEXT](../CONTEXT.md)，不新增通用 UI 术语。

## 验证

复用已确认的应用级 widget 测试边界：挂载真实应用，点击、拖动、切页，检查实际可见结果、
过渡阶段、布局稳定性、实际卡片构建范围和请求次数。通过测试期的 Flutter 构建回调记录
所有构建过的卡片，包括同帧构建后回收的卡片。覆盖远距离回顶、手势中断、恢复阅读位置后
的真正顶部及减少动画。运行 Flutter 静态分析、格式检查及完整测试。

验证结果：`flutter analyze`、Dart 与根目录格式检查通过，完整 Flutter 测试 512 项通过；
规范与需求两项代码审查均无剩余发现。200 条版本数据的远距离回归记录实际构建过的卡片，
在过渡期间保持少于 24 张；保留旧中心布局身份时，同一测试曾记录到 71 张。

测试结果只能证明行为及访问的卡片范围，不证明 Android 设备帧率。按用户最新要求，
不启动浏览器、不做设备自动化或实际性能录制，由用户在 Android 上验收动画手感。
