# Keep the Flutter timeline reading session in a provider and derive the view state

The Release Timeline's reading position, its refresh presentation flags and the count of refreshes that have landed belong to a reading session owned by a provider, not to the destination widget. The shell builds only the selected destination, so a destination-owned session would lose a round that landed while the reader was on Follows or Settings. The session's subscription to the timeline session therefore lives in the provider's own build and never in a widget: a listener registered by a widget is created when that widget mounts, so it never sees a change that happened while the widget was gone, and the round it was waiting for would never settle.

A landed refresh is settled when the timeline session publishes, which is before any widget rebuilds in that frame. This ordering is load-bearing rather than incidental. The landed count is compared across a build pair by the list to decide whether the newest releases are presented from the top, so the count must already hold its new value when the list subtree is built. Settling from the completed round's future was rejected for this reason: it runs after the publish, where the count can change a frame late or, if the value is kept silent, not at all. The scroll anchor stays a silent field on purpose — a scroll frame reports the release being read, and publishing that per frame would rebuild the list it is measuring.

The reader-facing timeline state is a derivation, not a copy: it composes the content module's snapshot with the presentation projection, and every content value is read through the snapshot. The earlier state declared the content's fields a second time and copied them by hand on each publish, so a content field that was not copied shipped as a silent default and no test failed. The presentation projection now derives itself from a content window, reusing itself when the same window returns and projecting another window under the filters it already holds; it deliberately does not carry a prepared search, which indexes the releases of the window it was built from. Additive state changes fail to compile rather than defaulting.

The content module receives the session's scope, generation, invalidator and currency predicate as one narrow operation context rather than four separate callbacks, and its other dependencies stay separate: retention-window resolution is a device-preference read and publication is an output channel, so neither is session validity. The session keeps its generation authority unchanged, as ADR 0038 requires — there is no second account generation, and the roughly forty currency checks spread across the module's await points stay where they are. A wrapper that hid those checks was rejected: they guard different continuations, and hiding them would bury the points where concurrent work stops.

The module is named for its lifetime and role, not for the value it owns: it owns a Timeline Reading Position, it is not one. `CONTEXT.md` is unchanged, on the same reasoning the cycle-recovery design record used for the fetched-page journal. Two places where that design record and the code disagreed were reconciled in favour of the record: the projection is now derived from the read-only snapshot rather than declared twice, and session validity is now one narrowly scoped context rather than four loose callbacks.

Splitting `SessionController` was considered and declined. Its browser sign-in flow would be a bidirectional seam: the extracted coordinator would still write session state, invalidate the request scope that cancels every in-flight request, advance the restore serial and re-enter sign-in. An identity store would have one caller and one adapter, so deleting it would only move the same complexity back into that caller.

Behaviour tests keep the mounted reading-position suite unmodified, including the round that lands while another destination is open, and drive the new provider seam directly in a container: a landed round, a failed round, a filter change, a begin that started no round, and an account change.
