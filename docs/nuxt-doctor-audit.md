# Nuxt Doctor audit

Audited with `vite-doctor@0.1.0` against Nuxt 4.6.2. The source baseline is
`32e85346bed323d5ae3ab6a8e1414e4e4a8a9b0d`, including the pending Skill Hub and
Doctor dependency setup. Reproduce with `bun run doctor`; reports include
framework extensions and scan the whole web application.

## Results

| Run                                          | Errors | Warnings | Info |
| -------------------------------------------- | -----: | -------: | ---: |
| Initial standalone audit                     |     10 |      130 |    2 |
| Nuxt manifest enabled, before project policy |     10 |      520 |    2 |
| After fixes and documented project policy    |      0 |       72 |    2 |

The manifest reveals 390 `NUXT0036` import-style suggestions. That rule is
disabled because the repository deliberately retains explicit Vue and named
utility imports, including modules loaded directly by Bun tests. This does not
change the existing convention for auto-imported app composables/default utils.
The rule's removal is a policy decision, not a source-code fix.

Four error findings were addressed in code: the font-settings head entry now
registers before asynchronous loading, translated login tips and autocomplete
highlights render as Vue text nodes, and Markdown images declare their existing
alt fallback explicitly. Six confirmed false positives have local, reasoned
`doctor-disable-next-line` comments: five HTML sinks generated by Shiki/Mermaid
or passed through the existing xss sanitizers, and one imperative DOM scroll
handle. Security rules remain enabled elsewhere.

The 58 resolved warnings cover request-scoped runtime config (8), explicit
action-button types (44), deterministic date/ID hydration (2), SEO composables
(2), image dimensions (1), and stable wiki diagram identity (1).

Menu and autocomplete listeners now belong to their opening watcher, which also
cancels pending repositioning work. Tests cover initially open panels, closing,
reopening, unmounting, literal search highlights, and provider discovery with
different request configs. Real Unhead SSR/client tests also check that font
settings render as root inline styles, preserving their precedence over global
stylesheet defaults and their reactivity after settings changes.
Doctor 0.1.0 still reports some of these cleanup
sites despite their registered cleanup callbacks.

Static generation exposed a separate configuration gap: the crawler attempted
to render `/native-login` without a browser sign-in proof and received HTTP 400.
Both the plain and localized route rules now declare `prerender: false`; the
approval page remains dynamically server-rendered with the same proof checks.
The localized prerender rule uses `/*/native-login`: Nitro 2's radix matcher does
not match the middle `**` in the existing Nuxt layout rule. A runtime matcher test
covers both paths and leaves ordinary pages eligible for prerendering.

## Retained diagnostics

These findings remain visible for future review; no warning baseline hides them.
The categories below describe why a mechanical fix would be inappropriate, not
a blanket exemption for future code in those files.

| Code       |  Count | Review context                                                                                                                                                              |
| ---------- | -----: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NUXT0019` |      2 | Nested store/session modules have explicit import entrypoints; they are not relying on recursive auto-imports.                                                              |
| `NUXT0029` |     17 | Browser helpers and event callbacks need their callers considered; adding `ClientOnly` everywhere would change rendering.                                                   |
| `NUXT0037` |     23 | Includes deliberately public provider/login routes and private handlers behind custom wrappers. Known GitHub guards are configured, but Doctor cannot follow every wrapper. |
| `TS0005`   |      3 | Signed-cookie parsing, authenticated handoff decoding, and generic storage deserialization need their validation/trust boundaries considered.                               |
| `VUE0004`  |     18 | Resources use watcher cleanup, `onBeforeUnmount`, or named disposal helpers that the heuristic does not consistently recognize.                                             |
| `VUE0020`  |      2 | Timeline anchoring intentionally reads the old DOM before patching; the other watcher reads a media query, not updated element geometry.                                    |
| `VUE0021`  |      7 | Watchers register cleanup callbacks, including the existing search debounce timer.                                                                                          |
| `NUXT0006` | 2 info | Autocomplete avatars and Markdown media retain raw image loading; Markdown includes private repository resources, source sets, and deferred loads.                          |

Doctor is an additional review aid. Formatting, lint, typechecking, Bun behavior
tests, and static generation remain the validation gates documented in
`CONTRIBUTING.md`. A clean error count does not replace reviewing the retained
warnings or the narrowly suppressed sinks when their data flow changes.
